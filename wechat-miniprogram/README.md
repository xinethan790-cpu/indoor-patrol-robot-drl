# 室内智能巡检微信小程序

这是毕业设计的原生微信小程序演示端，不依赖第三方前端框架。小程序以只读方式展示机器人位置与轨迹、动态障碍物、PPO 避障决策、巡检任务进度、温度/烟雾/一氧化碳数据、活动告警、异常记录、终态结果和巡检历史。

## 已实现页面

- **巡检总览**：深色 Canvas 地图、动态障碍与速度箭头、PPO→安全过滤→执行动作、最近障碍/TTC、P1～P4 状态、环境读数、活动告警和结果入口。
- **异常记录**：按全部、触发、解除和严重级别筛选告警时间线。
- **巡检结果**：覆盖、碰撞、采样、告警、运行时间、路径长度、最小净空和运行身份。
- **巡检历史**：分页展示固定设备的任务摘要，区分正在巡检、运行中断、异常中止、正常完成、未验证终态和旧版终态。
- **关于项目**：系统能力、数据模式、接口地址和演示边界。

## 0.2.0 数据模式

### 1. 云端实时同步（默认）

小程序已绑定 CloudBase 环境 `cloud1-5gpkygv2be4de05a`，只读监听集合 `patrol_live` 的固定文档 `main`：

```text
Mac / Webots 仿真
        ↓ 服务端鉴权上报（密钥只在 Mac）
CloudBase patrol_live/main
        ↓ 小程序只读 watch
微信真机巡检看板

CloudBase patrol_runs
        ↓ 登录鉴权 + getPatrolHistory 字段白名单
微信真机巡检历史
```

云端快照协议为 `patrol-cloud-snapshot/v1`，文档结构如下：

```json
{
  "_id": "main",
  "schema_version": "patrol-cloud-snapshot/v1",
  "device_id": "macmini-m4",
  "run_id": "...",
  "sequence": 123,
  "terminal": false,
  "body_sha256": "64 位十六进制摘要",
  "received_at_utc": "2026-09-01T06:00:00.000Z",
  "received_at_epoch_ms": 1788242400000,
  "payload": { "schema_version": "patrol-dashboard/v1" }
}
```

其中 `payload` 是未经改形的完整看板 DTO；顶层 `run_id`、`sequence` 和 `terminal` 必须与 `payload.run` 一致。客户端会先深度检查地图、轨迹、任务、传感器、告警、结果及数组边界，再交给原有 `run_id + sequence` 协议门禁。运行态、终态标记、结果可用性、验证结论、巡检点计数和进度比例必须属于同一个生命周期状态；矛盾组合会在进入页面状态前失败关闭。

实时连接具备以下保护：

- 云环境已连接但尚无 `patrol_live/main` 时进入“等待巡检任务”，保持实时观察；若实时订阅
  已降级，则按固定 2 秒间隔轮询等待，不把正常空库计为连接失败或指数退避；
- `watch` 中断后自动关闭观察器并降级为每 2 秒一次的只读轮询；
- 只有收到更大的 `sequence` 才算新鲜数据，连续 8 秒无新序号会显示“数据停滞”；
- 同序号不同内容、序号回退、运行证据混入、协议不匹配都会失败关闭；
- App 只维护一个共享连接，切换总览、告警、结果页面不会重启回放或断开云端观察器；
- 页面隐藏时停止高频界面更新并只缓存最新快照，返回页面后一次性刷新；整个小程序进入后台时才暂停连接；
- 切换数据模式会原子清空上一来源的地图、告警和结果，空云端不会残留演示数据；
- 终态保留结果并继续等待下一次合法巡检；
- 同一连续会话已经接收有效快照后，`main` 被删除会失败关闭，不会伪装成首次等待；未登录
  身份返回的 `AUTH_REQUIRED` 同样不会被空库状态掩盖；
- 客户端不包含 AppSecret、上报 Token、API Key 或任何写入凭证。

云数据库需预先创建 `patrol_live` 和服务端私有的 `patrol_runs` 集合。前者配置为“小程序端只读、客户端禁止写入”，后者禁止客户端直接读取和写入，只能通过登录鉴权的 `getPatrolHistory` 获取固定设备的摘要字段。历史响应不包含终态负载、请求哈希、nonce、签名或密钥。分页游标使用服务端 HMAC 防篡改，客户端按 `run_id` 去重，并支持下拉刷新与错误恢复。没有符合协议的 `main` 文档时，总览会保持等待状态，不会伪造实时数据。

### 2. 仿真演示回放

内置数据来自已校验运行 `graduation-demo-seed7000-v1`。导出脚本将 823 条原始状态等距保留为 90 帧，同时强制保留开始、终态、四次到点采样、六条告警事件和临界避障/脱困附近的关键状态。90 帧中有 70 帧包含与原始控制步精确匹配的动态障碍与避障遥测；没有对应原始证据的帧明确标记为不可用，不进行插值或编造。

回放结果固定为：

- 4 / 4 个巡检点；
- 0 次物理碰撞；
- 36 条环境样本；
- 3 次告警触发、3 次解除；
- 实际路径 11.74 m；
- 最小净空 0.186 m。

回放还可直接展示最近 LiDAR 距离、稳健 TTC、PPO 原始动作、安全过滤动作、最终执行速度、安全盾介入和有界脱困状态。这些字段属于应用可解释性证据，不构成形式化安全保证。

该模式不请求网络，开发者工具和真机预览均可完整运行。页面始终标注“仿真演示”，不会把回放冒充真实机器人实时数据。

### 3. 电脑本地实时

先在仓库根目录启动看板：

```bash
python scripts/run_patrol_dashboard.py \
  --run-dir artifacts/results/graduation-demo-seed7000-v1 \
  --port 8765
```

然后在小程序“项目”页选择“电脑本地实时”。默认接口为：

```text
http://127.0.0.1:8765/api/dashboard
```

`project.config.json` 已为本地开发关闭合法域名校验。此模式只适用于同一台 Mac 上的微信开发者工具；手机的 `127.0.0.1` 是手机自身，真机若选择本机模式会自动降级到云端实时模式。

## 导入微信开发者工具

1. 在仓库 `cloudfunctions` 目录执行 `npm run build`，生成开发者工具可见但不提交 Git 的
   `wechat-miniprogram/cloudfunctions/` 自包含部署目录。
2. 打开微信开发者工具并选择“小程序”，再选择“导入项目”。
3. 项目目录选择本文件所在的 `wechat-miniprogram` 目录。
4. 当前配置已绑定 AppID `wx081cd599c38261c7`；请使用拥有该小程序开发权限的微信账号登录。
5. 点击“编译”，新安装默认进入云端实时模式；也可以在“项目”页切换到仿真演示回放。
6. 若左侧没有显示云函数目录，关闭项目、重新打开，并确认当前环境为
   `cloud1-5gpkygv2be4de05a`。

项目未调用手机号、位置、通讯录、相册、摄像头等隐私接口，也不包含 Token、上传密钥或其他服务端秘密。当前源码、本地构建和部署清单的更新不会改变微信后台正在审核的版本；只有再次执行“上传”并重新提交审核才会产生新审核包。

## 测试

要求本机已安装 Node.js。运行：

```bash
npm test
```

测试覆盖：

- 离线夹具与终态指标；
- 轨迹增长、传感器和告警时间线；
- 协议版本、`run_id`、重复/回退/冲突序号；
- CloudBase 快照元数据一致性、实时订阅、轮询降级与 8 秒停滞检测；
- 旧版 `patrol-dashboard/v1` 快照的受限兼容与三端滚动部署顺序；
- 真机本地模式自动降级和三种数据模式策略；
- 请求超时、指数退避与终态停止；
- 地图坐标变换、动态障碍边界与绘制半径保护；
- 共享会话、页面隐藏缓存、模式切换清空和避障决策投影；
- 历史分页、同页/跨页去重、活动状态定时刷新、空状态、错误恢复、旧版终态与敏感字段拒收；
- 页面数据投影、告警筛选与结果指标。

重新导出内置证据（同时生成可审计 JSON 和小程序可加载的 CommonJS 数据模块）：

```bash
npm run export:demo
```

导出器读取已有巡检证据，并通过后端仓库与投影层执行完整性校验后才会写入夹具。

## 云端联调检查

1. 在云开发控制台确认当前环境为 `cloud1-5gpkygv2be4de05a`。
2. 确认 `patrol_live/main` 存在且符合上述快照协议。
3. 确认小程序端对该集合只有读取权限，不能新增、修改或删除文档。
4. 启动 Mac 仿真上报后观察 `sequence` 持续增加，再用开发者工具和真机各验证一次。
5. 停止 Mac 上报，确认 8 秒后页面明确显示数据停滞；恢复上报后应随新序号自动恢复在线。
6. 断开实时订阅或临时制造 watch 错误，确认页面显示“轮询保障”且仍能接收新序号。
7. 确认四个云函数均已部署；`getPatrolHistory` 与 `ingestPatrol` 配置相同的
   `PATROL_RELAY_UPLOAD_SECRET`，但密钥不进入源码或小程序。
8. 打开“历史”页，确认新任务可自动出现；停留在页面时，8 秒无新快照后状态也会自动刷新为
   “运行中断”；分页重复会按 `run_id` 去除，篡改游标只显示安全的暂不可用提示。

云端模式仍然只是仿真系统的远程可视化端，不提供机器人运动控制。二维地图也不代表真实场地测绘或导航安全边界。
