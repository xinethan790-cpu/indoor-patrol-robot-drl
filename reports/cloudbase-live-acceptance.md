# CloudBase 真实链路验收记录

更新时间：2026-09-02。

## 当前状态

仓库已经完成 Webots 状态投影、Mac HTTPS/HMAC 中转、CloudBase 云函数、数据库规则、微信小程序只读客户端及三端离线契约测试。真实云资源、HTTP 访问服务和真机链路尚未在本记录中留下可复核证据，因此当前状态为 **待部署验收**，不能把“代码已实现”表述为“真实链路已上线”。

任何真实上传密钥、签名、nonce、AppSecret 或访问令牌都不得写入本文件、终端截图、日志或 Git。

## 上线门禁

按顺序执行；前一项未通过时不得启动下一项。

1. 本地运行 Python、小程序和 Cloud Functions 全部测试，并完成云函数 bundle 校验。
2. 使用候选真实密钥在本机执行 `npm run preflight:secret`；命令只报告可用性，不打印密钥。
3. 部署云函数后，在控制台重新确认 `ingestPatrol` 与 `getPatrolHistory` 的 `PATROL_RELAY_UPLOAD_SECRET` 均存在且一致。CloudBase CLI 对未声明环境变量是否保留不得靠猜测；若部署清除了变量，应先恢复密钥，再继续。
4. 确认四个集合、三个索引、数据库规则、函数权限、HTTP 路由、限频、配额和费用告警均已生效。
5. 在不启动持续 relay 的情况下发送一条合法 HMAC canary；只有返回的 ACK 与设备、运行编号、序号和请求体摘要全部一致才算通过。
6. 分别验证过期时间戳、重复 nonce、错误签名、超大请求体和序号回退都会被拒绝，并确认日志不包含秘密或完整请求体。
7. 启动一次新的 Webots 巡检；核对 `patrol_live/main` 序号单调增加、终态进入 `patrol_runs`，开发者工具与微信真机显示同一 `run_id` 和终态指标。
8. 调用 `getPatrolHistory`，确认只允许登录用户读取固定设备、分页游标篡改被拒绝、旧记录明确显示为旧版终态，并且响应不含终态负载、请求哈希、nonce、签名或密钥。
9. 对新普通终态调用 `getPatrolReport`，确认返回 `patrol-report-response/v1`，运行编号、轨迹末点、P1～P4 读数和告警时间线与本地证据一致；活动任务、旧记录、异常中止和截断告警均不能产生完整报告。
10. 停止上报，确认 8 秒后小程序显示数据停滞；恢复后自动回到在线。切换页面不得重启任务，切换到空数据源不得残留演示地图、告警或结果。
