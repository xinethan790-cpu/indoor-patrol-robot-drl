# 实验与复现方案

## 1. 验证层次

1. 纯 Python 单元测试：观测、动作、奖励、终止、A*、指标和随机化；
2. Gymnasium 接口测试：`check_env`、长时间随机动作和重复 reset；
3. Webots 集成测试：真实传感器与控制闭环的短 episode；
4. 离线批量评测：PPO、DWA、规则法在相同场景上的正式比较。

完整 PPO 训练和正式批量实验不放入 GitHub Actions。CI 只运行快速、确定的纯 Python 测试。

## 2. 随机种子

- 正式训练：`11、22、33`；
- 参数选择与验证：`5000～5019`；
- 最终测试：`10000～10019`。

全部方法必须使用同一组测试场景。每次训练保存配置、seed、Git commit、Python/依赖/Webots 版本和地图文件哈希。

验证集可以用于选择 checkpoint 和调整超参数，最终测试集不能参与任何选择。运动学脚本要求显式传入 `--confirm-test`；正式 Webots held-out test 则必须通过 `scripts/run_webots_formal_test.py` 执行，由 runner 注入 Controller 所需的 test 环境变量，并同时校验 final lock 与 campaign 无关的全局一次性 ledger。完整执行命令见[训练复现协议](training-protocol.md)。

## 3. 对比方法

| 方法 | 全局规划 | 局部避障 |
|---|---|---|
| 规则基线 | A* | LiDAR 分区规则 |
| 经典基线 | A* | DWA |

随机策略只用于冒烟测试，不作为论文主要对照。

## 4. 正式场景矩阵

| 条件 | 地图 | 动态障碍 | 目的 |
|---|---|---|---|
| G0 | 训练地图 A | 训练范围 | 标准测试 |
| G1 | 未见地图 B | 训练范围 | 布局泛化 |
| G2 | 地图 A | 更高密度 | 密度泛化 |
| G3 | 地图 A | 更高速度 | 速度泛化 |

每个条件使用 20 个固定场景。两种传统基线各评测一次，PPO 汇总三个独立训练种子，共 `4 × 20 × (2 + 3) = 400` 个 episode。

当前已完成的 240 回合表是 seed 11 的**运动学验证基准**，不是上述 Webots 正式场景矩阵，也不替代三独立训练 seed 的统计。当前真实数据与剩余项见[实验进展](../reports/current-progress.md)。

## 5. 指标

- 成功率、碰撞率、超时率；
- 成功 episode 的完成时间和路径长度；
- 路径长度与 A* 最短路径之比；
- 最小安全距离和近碰撞比例；
- 动作变化量或角速度变化；
- 单步决策延迟 P50/P95；
- 完整巡检任务的航点完成率。

每个 episode 保存一行 CSV，失败案例另存逐步轨迹。绘图脚本只从原始数据生成图表，避免手工整理结果。

## 6. 消融实验

最小消融只做两个：

- 移除安全距离奖励，观察碰撞率和最小间距；
- 移除动态场景随机化，观察未见地图与高速障碍泛化。

如果时间充足，再增加“移除 LiDAR 帧差”或“移除动作平滑惩罚”，不同时展开大量组合。

## 7. 完成条件

项目完成不要求 PPO 在所有指标上全面超过 DWA。验收条件是系统可运行、比较公平、实验可复现、结果有量化证据，并能解释 PPO 的优势、失败模式和适用边界。
